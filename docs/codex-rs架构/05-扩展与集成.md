# Codex Rust: 扩展与集成

这一层负责：

- MCP client / server
- skills 加载
- IDE/外部前端接口
- 配置与 profile
- sandbox / exec server 等外围系统

## 1. 文件拆分

- `core/src/mcp_connection_manager.rs`
- `core/src/mcp/`
- `mcp-server/`
- `exec-server/`
- `app-server/`
- `app-server-protocol/`
- `core/src/skills/manager.rs`
- `core/src/skills/loader.rs`
- `core/src/config/`
- `core/src/config_loader/`
- `execpolicy/`
- `linux-sandbox/`
- `windows-sandbox-rs/`

## 2. MCP 在 Codex Rust 里的位置

`mcp_connection_manager` 很清楚地承担了 MCP client 聚合层职责：

- 每个配置 server 建一个 client
- 聚合所有 server 的 tool
- 对 tool 名做限定和 sanitize
- 处理 elicitation 和 auth 状态

和 Claude Code 相比，它的 MCP 组织方式更像基础设施服务，而不是 REPL 状态的一部分。

## 3. skills 体系

`skills/manager.rs` 和 `skills/loader.rs` 表明：

- skill roots 来自 config layer stack
- 有 repo / user / system / admin scope
- 会按 scope 优先级去重
- 会做缓存

这点和 Claude Code 很像，但有两个明显不同：

1. 更依赖 config layer stack
2. skill 注入时更偏显式 user input mention

## 4. config / profile / layer stack

Codex Rust 在配置层更重：

- `config/`
- `config_loader/`
- profile
- layer merge
- overrides
- fingerprint

这部分比 Claude Code 的配置与迁移层更“系统工具化”，因为它要支撑多个前端和多个运行模式。

## 5. exec-server / app-server 的意义

这些 crate 说明 Codex Rust 不只是在做本地 CLI：

- `exec-server`
  更贴近执行服务和 wrapper
- `app-server`
  更贴近外部客户端/应用侧接入
- `mcp-server`
  允许 Codex 反过来作为 MCP server 暴露能力

所以它的扩展面更像平台，而不只是 agent 产品功能。

## 6. 和 Claude Code 的主要差异

### 6.1 相同点

- 都有 MCP
- 都有 skills
- 都有配置和多来源扩展

### 6.2 不同点

- Codex Rust 的扩展层更平台化、服务化
- Claude Code 的扩展层更贴近 REPL 产品能力

## 7. 一句话总结

Codex Rust 的扩展与集成层更像：

- 一套为“原生核心库 + 多前端 + 多执行入口”服务的基础设施层
