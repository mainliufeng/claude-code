# Codex Rust: 工具能力、执行与结果回流

这一层负责：

- 定义有哪些工具
- 把工具暴露给模型
- 接 tool call
- 处理权限与 sandbox
- 执行工具并把结果写回会话

## 1. 文件拆分

- `core/src/tools/spec.rs`
- `core/src/tools/router.rs`
- `core/src/tools/orchestrator.rs`
- `core/src/tools/registry.rs`
- `core/src/tools/context.rs`
- `core/src/tools/parallel.rs`
- `core/src/function_tool.rs`
- `core/src/exec.rs`
- `core/src/unified_exec/`
- `core/src/bash.rs`
- `core/src/apply_patch.rs`

## 2. 结构比 Claude Code 更“后端化”

Claude Code 的工具体系更像：

- Tool 定义
- Tool pool
- Tool execution

Codex Rust 则更明确地拆成：

- `spec`
  tool schema / tool shape
- `registry`
  tool 注册
- `router`
  识别并派发具体 tool call
- `orchestrator`
  approval + sandbox + retry 统一编排
- `runtime`
  具体执行

这个拆法更像后端服务里的请求路由与执行管线。

## 3. `ToolRouter`

`core/src/tools/router.rs` 负责两件核心事：

1. `build_tool_call(...)`
   从模型返回的 `ResponseItem` 识别出：
   - FunctionCall
   - CustomToolCall
   - LocalShellCall
   - MCP tool call
2. `dispatch_tool_call(...)`
   把它分发给 registry 中对应的处理器

这说明 Codex Rust 里的 tool call 解析是显式路由的，不像 Claude Code 更偏在主循环里直接分支。

## 4. `ToolOrchestrator`

`core/src/tools/orchestrator.rs` 是一个很重要的中层，统一处理：

1. approval
2. sandbox selection
3. first attempt
4. 必要时无沙箱重试

这部分和 Claude Code 非常像，但实现风格更统一：

- Claude Code 是权限和工具执行链更分散地串在一起
- Codex Rust 则显式做成了一个 orchestration object

## 5. tool result 如何回流

在 Codex Rust 里，工具执行成功后会回成：

- `FunctionCallOutput`
- `CustomToolCallOutput`
- 或本地 shell 输出对应的 `ResponseInputItem`

这些结果随后进入 `ContextManager`，成为下一轮 prompt 的输入。

也就是说：

- 它没有像 Claude Code 那样大量使用 attachment message 当中间桥
- 更偏向把结果直接收敛成协议层的 `ResponseItem / ResponseInputItem`

## 6. sandbox / execpolicy 是一等公民

从 `orchestrator`、`execpolicy`、`linux-sandbox`、`windows-sandbox-rs`、`exec-server` 这些 crate 能看出：

- Codex Rust 对“本地执行约束”投入更大
- 它把 approval、sandbox、execpolicy、平台差异做得更系统化

这也是它和 Claude Code 在工程风格上的一个明显差异：

- Claude Code 更偏产品/agent runtime 一体化
- Codex Rust 更偏系统工具 / 原生执行平台

## 7. 和 Claude Code 的关键差异

### 7.1 相同点

- 都有工具 schema
- 都有 permission / approval
- 都有 tool result 回流上下文
- 都支持 shell、patch、MCP

### 7.2 不同点

- Codex Rust 的 router / orchestrator / registry 分层更明确
- tool result 更直接回到协议消息，不太依赖 attachment 中转
- sandbox 和执行策略是更重的系统级基础设施

## 8. 一句话总结

Codex Rust 的工具体系更像：

- 一个原生 agent runtime 的“工具请求路由 + 执行编排 + 协议回流”管线
