# Codex Rust: 会话与运行时

这一层负责：

- 会话生命周期
- task 运行
- TUI / exec / cli 前端挂载
- 线程、状态和事件分发

## 1. 文件拆分

- `core/src/codex.rs`
- `core/src/codex_thread.rs`
- `core/src/tasks/mod.rs`
- `core/src/state/session.rs`
- `tui/src/`
- `tui2/src/`
- `exec/src/`
- `cli/src/main.rs`

## 2. `SessionTask` 是运行时骨架

`core/src/tasks/mod.rs` 里，`SessionTask` trait 抽象了：

- `RegularTask`
- `ReviewTask`
- `CompactTask`
- `GhostSnapshotTask`
- `UndoTask`
- `UserShellCommandTask`

这意味着 Codex Rust 的“一个回合”不是散在 UI 里，而是被抽象成明确的 task 类型。

## 3. `spawn_task` / `abort_all_tasks`

Session 在运行时做的事情很明确：

- `spawn_task(...)`
- `abort_all_tasks(...)`
- `on_task_finished(...)`

和 Claude Code 相比：

- 都有任务概念
- 但 Codex Rust 的任务更偏核心 runtime 抽象
- Claude Code 的 task 和 UI 展示关系更紧

## 4. TUI 只是前端，不是主循环中心

`tui/src/lib.rs` 和 `tui2/src/lib.rs` 主要负责：

- 启动配置
- 登录校验
- 选择 sandbox / approval 策略
- 组装 App / TUI

但真正的 agent 主循环并不在这里。

这点和 Claude Code 差异很大：

- Claude Code 的 `REPL.tsx` 是运行时非常核心的一层
- Codex Rust 的 TUI 更像 `core` 的一个前端壳

## 5. CLI 多入口结构

`cli/src/main.rs` 可以看出 Codex Rust 顶层是多工具入口：

- `exec`
- `review`
- `login/logout`
- `mcp`
- `mcp-server`
- `app-server`
- `sandbox`
- `resume/fork`
- `cloud`

这种结构也说明：

- Codex Rust 的核心能力设计目标不只是交互式终端
- 它更像一套平台，可挂多种入口

## 6. 和 Claude Code 的主要差异

### 6.1 相同点

- 都有 session / task / turn 生命周期
- 都支持 resume / fork / review / compact 等变体流程

### 6.2 不同点

- Codex Rust 的运行时抽象更偏核心库
- Claude Code 的运行时抽象更偏 REPL / UI 驱动
- Codex Rust 的 TUI 更像可替换前端

## 7. 一句话总结

Codex Rust 的运行时层更像：

- 一个任务化、事件驱动、前端可替换的核心 agent runtime
