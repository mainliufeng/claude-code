# Go Agent Core 包结构与接口

这一份把目标架构落到更具体的包和接口层。

## 1. 包结构建议

```text
/pkg/agentcore/protocol
/pkg/agentcore/engine
/pkg/agentcore/model
/pkg/agentcore/context
/pkg/agentcore/session
/pkg/agentcore/memory
/pkg/agentcore/compact
/pkg/agentcore/tooling
/pkg/agentcore/approval
/pkg/agentcore/events

/pkg/support/skillfs
/pkg/support/mcpbridge
/pkg/support/toolfs
/pkg/support/toolbash
/pkg/support/toolpatch
/pkg/support/toolgit

/pkg/storage/sessionstore
/pkg/storage/memorystore
/pkg/storage/artifactstore

/pkg/serviceapi
```

建议职责如下。

## 2. `protocol`

负责定义核心共享数据结构，不放业务逻辑。

建议包含：

- `SessionID`
- `TurnID`
- `ToolCallID`
- `Message`
- `TurnItem`
- `Prompt`
- `PromptTool`
- `ToolCall`
- `ToolResult`
- `ContextRecord`
- `ArtifactRef`
- `SummaryRecord`
- `ApprovalDecision`

推荐把 `TurnItem` 作为统一历史记录抽象：

```go
type TurnItemKind string

const (
    TurnItemSystem          TurnItemKind = "system"
    TurnItemDeveloper       TurnItemKind = "developer"
    TurnItemUser            TurnItemKind = "user"
    TurnItemAssistant       TurnItemKind = "assistant"
    TurnItemContextInjection TurnItemKind = "context_injection"
    TurnItemToolCall        TurnItemKind = "tool_call"
    TurnItemToolResult      TurnItemKind = "tool_result"
    TurnItemSummary         TurnItemKind = "summary"
)

type TurnItem struct {
    ID        string
    SessionID string
    TurnID    string
    Kind      TurnItemKind
    Role      string
    Text      string
    Payload   map[string]any
    CreatedAt time.Time
}
```

这个统一抽象的作用是：

- 让 skill injection、tool result、summary、普通消息都进一套历史
- compact 不需要知道太多底层来源，只需要识别 item kind

## 3. `engine`

这是主循环模块。

它的职责：

- 发起 turn
- 调上下文装配
- 调模型
- 识别 tool call
- 调工具执行编排
- 把结果并回历史
- 触发 compact / memory extract

核心接口：

```go
type Engine interface {
    RunTurn(ctx context.Context, req *RunTurnRequest) (<-chan Event, error)
}

type RunTurnRequest struct {
    SessionID string
    Inputs    []UserInput
    Options   TurnOptions
}
```

## 4. `model`

只做 provider 适配，不参与业务编排。

```go
type Provider interface {
    Stream(ctx context.Context, prompt *Prompt) (<-chan ModelEvent, error)
    Complete(ctx context.Context, prompt *Prompt) (*ModelResponse, error)
}
```

需要支持：

- OpenAI Responses
- Anthropic Messages
- 未来可能的兼容 provider

关键约束：

- `engine` 不直接知道底层 API 形态
- provider 适配器负责把 `Prompt` 编译到具体 API

## 5. `context`

负责把“当前轮要给模型看的内容”组装出来。

拆成两个概念：

- `Source`
  上下文来源
- `Assembler`
  组装器

```go
type Source interface {
    Name() string
    Collect(ctx context.Context, req *ContextRequest) ([]ContextRecord, error)
}

type Assembler interface {
    Build(ctx context.Context, req *AssembleRequest) (*PromptInput, error)
}
```

典型 source：

- session history
- user instructions / AGENTS
- skills
- memory
- project docs
- MCP resources
- tool-result restore

这里直接借鉴 Claude Code 的业务思想：

- 不把所有东西都塞进 system prompt
- 用统一的 context injection 机制组织动态上下文

## 6. `session`

负责 session / thread / turn 生命周期与持久化接口。

```go
type Store interface {
    CreateSession(ctx context.Context, s *Session) error
    GetSession(ctx context.Context, sessionID string) (*Session, error)
    AppendItems(ctx context.Context, sessionID string, items []TurnItem) error
    ListItems(ctx context.Context, sessionID string, opts ListItemsOptions) ([]TurnItem, error)
    ReplaceHistory(ctx context.Context, sessionID string, items []TurnItem) error
}
```

关键原则：

- `session` 只关心历史和元信息
- 运行时附加状态不要污染持久化模型

## 7. `memory`

建议拆成：

- `SessionMemory`
- `PersistentMemory`
- `Extractor`

```go
type Extractor interface {
    Extract(ctx context.Context, req *ExtractRequest) ([]MemoryFact, error)
}

type MemoryStore interface {
    UpsertFacts(ctx context.Context, scope MemoryScope, facts []MemoryFact) error
    QueryFacts(ctx context.Context, q *MemoryQuery) ([]MemoryFact, error)
}
```

这里要明确和 Claude Code 对齐的业务点：

- memory 不等于 transcript
- memory 是被提炼过的稳定事实

## 8. `compact`

这是最容易设计错的地方。

建议拆成 3 层接口：

```go
type Budgeter interface {
    Apply(ctx context.Context, items []TurnItem) ([]TurnItem, error)
}

type MicroCompactor interface {
    Apply(ctx context.Context, items []TurnItem) ([]TurnItem, error)
}

type FullCompactor interface {
    Apply(ctx context.Context, items []TurnItem, env *CompactEnv) (*CompactResult, error)
}
```

原因是业务上你要向 Claude Code 看齐，就不能只留一个 `Summarize(items)`。

最少也要表达：

- tool result budget
- 旧结果清理
- full compact

## 9. `tooling`

这是第二个大头。

建议拆成：

- `SpecRegistry`
- `Router`
- `Orchestrator`
- `Executor`

```go
type SpecRegistry interface {
    List(ctx context.Context, req *ListToolsRequest) ([]PromptTool, error)
    Resolve(name string) (ToolSpec, bool)
}

type Router interface {
    BuildCall(item ModelOutputItem) (*ToolCall, error)
}

type Orchestrator interface {
    Execute(ctx context.Context, call *ToolCall, turn *TurnRuntime) (*ToolExecutionResult, error)
}

type Executor interface {
    Execute(ctx context.Context, call *ToolCall, env *ExecutionEnv) (*ToolResult, error)
}
```

关键点：

- `tool schema` 和 `tool execution` 分开
- `approval + sandbox + retry` 在 orchestrator
- 真正做事的是 executor

## 10. `approval`

单独做，不嵌进工具实现里。

```go
type Manager interface {
    Decide(ctx context.Context, req *ApprovalRequest) (*ApprovalDecision, error)
}
```

要支持：

- never / on-request / strict
- tenant policy
- workspace policy
- tool-level policy
- session-level temporary approvals

## 11. 支持模块

这些都不是 `agentcore` 的一部分，而是外围实现：

### 11.1 `support/skillfs`

负责：

- 扫描 skill roots
- 解析 frontmatter
- 读取 skill 正文
- 构造 skill catalog

它向 core 暴露：

```go
type SkillCatalog interface {
    List(ctx context.Context, req *ListSkillsRequest) ([]SkillMeta, error)
    Resolve(ctx context.Context, name string) (*SkillDoc, error)
}
```

### 11.2 `support/mcpbridge`

负责：

- MCP server 生命周期
- tool/resources/prompts 聚合
- 名称限定和路由

它向 core 暴露：

```go
type MCPBridge interface {
    ListTools(ctx context.Context) ([]PromptTool, error)
    CallTool(ctx context.Context, req *MCPToolCall) (*ToolResult, error)
    ListResources(ctx context.Context) ([]ResourceMeta, error)
    ReadResource(ctx context.Context, uri string) (*ResourceDoc, error)
}
```

### 11.3 `support/toolfs`

负责本地文件读写、patch、搜索。

### 11.4 `support/toolbash`

负责命令执行、PTY、stdout/stderr 聚合、timeout、中断。

### 11.5 `support/toolpatch`

负责 apply patch / text edit / diff 生成。

## 12. 最小组合接口

如果你只想定义一个第一版最小内核，我建议最先稳定这 8 个接口：

- `Provider`
- `Store`
- `Assembler`
- `SpecRegistry`
- `Orchestrator`
- `Manager`
- `SkillCatalog`
- `MCPBridge`

## 13. 一句话总结

这一版包结构的核心思想是：

- `agentcore` 只保留稳定抽象
- 所有“靠近本地环境”的东西都下沉到 `support`
- 用统一 `TurnItem/Prompt/ToolCall/ToolResult` 把上下文链和工具链接起来
